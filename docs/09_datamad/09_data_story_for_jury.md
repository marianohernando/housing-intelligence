# DATAMAD — Data Story para el Jurado

## Mensaje
La plataforma no utiliza datos abiertos como simple decoración de un mapa.

Los convierte en:
- features;
- decisiones;
- recomendaciones;
- modelos;
- simulaciones.

## Estructura de storytelling

### 1. Dataset
“Comunidad de Madrid publica X.”

### 2. Transformation
“Lo normalizamos y lo llevamos a H3/microzonas.”

### 3. Feature
“De ahí calculamos acceso, affordability, gap...”

### 4. Decision
“Esto cambia qué zonas recomendamos.”

### 5. Value
“Ciudadano decide mejor / promotor entiende qué falta.”

## Métrica interna
Para cada funcionalidad del MVP:
- CM dataset count;
- external dataset count;
- features built;
- last update;
- lineage completeness.

## Regla
No inventar una cuota artificial como “70% debe venir de Madrid”.
La prioridad se demostrará por dependencia funcional y trazabilidad.
