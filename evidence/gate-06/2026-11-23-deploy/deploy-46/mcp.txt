5. Finding: Claude Code keeps one request open until Vercel's 300 s limit
   Claude Code 2.1.326 speaks protocol 2026-07-28. It sends 5 POSTs: server/discover, subscriptions/listen, prompts/list,
   resources/list and tools/list. The server (mcp 2.3.0) answers subscriptions/listen with a text/event-stream («notifications/
   subscriptions/acknowledged», toolsListChanged, promptsListChanged, resourcesListChanged) and keeps it open for list-changed
   notifications; the other four are JSON and close at once.
   In production that POST (11:21:41.594 UTC) stayed open until 11:26:41.646, exactly 300 s, Vercel's maximum duration, although
   claude -p had exited within seconds. While open, Vercel's runtime log attributes every line of that instance to it as well
   (251 lines), so lines appear twice in «vercel logs».
   Reproduced locally with a logging wrapper: the listen POST's body goes out with more_body=True and only completes at the
   client's disconnect. A plain curl client (initialize, tools/list, tools/call) never opens it.
   Impact: the MCP works; each Claude Code session (and any client that subscribes) holds one container request for up to 5 min
   (the instance keeps serving other requests meanwhile) and doubles the log lines of that instance. Not critical for the demo.
